# 原多体求解、柔性结果和载荷导出的兼容核对

本文核对仓库中的原 [mMotionSolverThread](../GUI/src/MainWindow/mMotionSolverThread.cpp)、[mMotionFlexBridge](../GUI/src/MainWindow/mMotionFlexBridge.cpp)、[mMotionAnimationPanel](../GUI/src/MainWindow/mMotionAnimationPanel.cpp) 和 [mMotionLoadExportPanel](../GUI/src/MainWindow/mMotionLoadExportPanel.cpp)，以及当前 OCC 适配入口。原界面中存在某个枚举或按钮，不等于原求解线程已经实现对应物理模型。

本轮没有替换 MotionEngine 算法，也没有用演示位移模拟柔性体。以下回归使用实际 Core / Modal 求解和实际 CAD 几何。它们验证表中具体工况，不构成所有材料、网格、机构或积分器组合的通用精度保证。界面拾取和完整导入工作流的独立记录见 [验证说明](native-motion-verification.md)。

## 已补齐的柔性结果链路

当前 [RigidFlexResult](../ModelData/src/MotionOcc/RigidMotion.h) 保存参考节点、表面三角形、源四面体拓扑、材料密度、模态数、唯一接口体数、完整 `psiInternal` 矩阵、初始接口位姿，以及每个接受时刻的接口位姿、模态坐标和实际节点位置。矩阵采用行优先的 `3N × (6K+m)` 布局；位姿四元数采用明确的 `w,x,y,z` 顺序。

原面板的三类显示量由 [FlexResultScalars](../ModelData/src/MotionOcc/FlexResultScalars.cpp) 独立计算：

| 显示量 | 计算含义 | 限制 |
| --- | --- | --- |
| 弹性位移 | `psiInternal` 的模态列乘模态坐标，逐节点取三维向量模长 | 排除前 `6K` 个边界自由度；刚体运动不会被画成弹性变形 |
| 总位移 | 当前实际世界节点减去初始参考节点，取模长 | 包含平移、旋转和弹性变形 |
| 原自由基投影 | 真实四面体集总质量、质量主轴和三项余弦基投影 | 保留原面板的显示算法；它是投影近似，不是导入 NX/MNF 自由模态，也不是应力结果 |

动画在相邻帧之间先插值节点向量或模态坐标，再计算模长。例如相反方向的等幅变形，其过零中间时刻必须为零，不能插值两个正的标量模长来代替。节点数量、矩阵维度和非有限值会被检查；失败时不覆盖此前有效显示数据。

### 参考系与发散处理

原 `mMotionFlexBridge` 曾把外部参考体原点移动到首个附着点，并重设 marker 世界位置。当前锁定引擎的 `FlexBodyBuilder` 已明确撤回这一步，因为它会破坏已解析约束。适配层继续使用初始质心参考系，而不是再次移动参考体原点。新增回归用质心和夹持点相差 5 mm 的柔性体，以 90°/s 转动 0.2 s；401 个接受帧的质心圆轨迹误差检查为 `1e-5 mm`，附着节点与接口体位姿的贴合检查为 `0.002 mm`。

原线程在引擎记录结果后的回调中发现模态发散，再按柔性干净帧数截尾。当前 [NativeMotionFlex](../ModelData/src/MotionOcc/NativeMotionFlex.cpp) 在记录前检查模态维度、有限性和原有的模态坐标平方和上限 `1e6`。多个柔性体先全部验证和暂存，全部有效后才共同追加。异常试算帧不会进入刚体、柔性体、控制器或通道结果。

结果终止原因明确区分 `EndTime`、`GeometryBoundary` 和 `FlexDivergence`。后两者可保留接受时刻的同步有效前缀，诊断包含异常试算时刻、最后有效时刻和原因；它们不被标为完成了原方案全时长。初始状态已经异常时，没有可以保留的有效初始帧，直接报告求解失败。批量 [MotionOccNativeCases](../tests/MotionOccNativeCases.cpp) 同样区分上述状态。

## 载荷导出恢复及物理修正

[NativeMotionLoadExport](../ModelData/src/MotionOcc/NativeMotionLoadExport.h) 提供以下独立服务，供结果导出界面调用：

| 功能 | 已实现行为 |
| --- | --- |
| 手动载荷 | 运动副、可用耦合副或驱动器；选择 I/J 端；指定帧、最大综合载荷帧或全部帧 |
| CSV | 可选六个力/力矩分量、缩放系数、有限元节点编号、真实时间及作用点；明确 N / mm / N·mm 单位 |
| BDF | `FORCE` / `MOMENT`，世界坐标系 `CID=0`，每个选中帧独立载荷集；目标点改变时正确换算力矩 |
| 特征工况 | 从分量局部极大/极小及合量局部极大选取，每个信号保留指定数量，按时刻容差合并 |
| 同步工况 | 同样选取特征时刻，每个工况同时包含所有选中运动副的该时刻载荷 |
| 结构初始参考系 | 依据选定分析体实际连接在 I 端还是 J 端，转换物理载荷及作用点到分析体初始位姿 |

源通道必须完整、有限、时间轴一致且单位匹配。文件通过 `QSaveFile` 原子写入，错误输入不会覆盖旧文件。平坦或严格单调历史没有内部局部峰值时，不凭空插入端点峰值。时间合并后的全部载荷取自同一个代表帧。

### I/J 端反力和力矩参考点

锁定引擎的原始 `ReactionForce/ReactionTorque` 表示 **J 端关于 J marker 的载荷**。原导出面板直接将它作为 I 端，J 端取反，会产生物理符号错误。当前原始曲线通道保持兼容；专业载荷导出明确换算为所选体受到的载荷：

```text
F_I = -F_J
M_I = -M_J + (p_J - p_I) × F_I
M_target = M_marker + (p_marker - p_target) × F
```

这不是凭命名推断。真实静力回归使用 1 kg 运动体，重力为 -9.81 m/s²，质心距离固定副 5 mm。原始 J 端结果为 `Fz=-9.81 N`、`My=+49.05 N·mm`；导出到 I 端后，`Fz=+9.81 N`、`My=-49.05 N·mm` 与重力平衡。将该载荷换到质心点后，力矩为零。另有分离 I/J marker 和旋转分析体的回归，检查力臂、旋转和平移，而不只检查文件是否生成。

原源码所引用的 `loadcase_format_spec.json` 未包含在仓库中。JSON 工况格式依据实际 `mMotionLoadExportPanel` 产生的 `info/bodies/joints/cases` 结构恢复，并纠正其力矩单位标记；没有声称对未提供的外部规范做过验证。

### 明确保留的载荷导出边界

旧 `couplings.Cable` 是含两个导向副、四个作用端的双向绳索耦合，其已有通道只表示首个端口。不能把一组反力整体取反，伪装为另一端完整物理载荷。当前专业导出会明确拒绝该来源，并提示使用导向副反力，或后续增加逐体耦合反力结果；这不影响该耦合本身求解。它与新增的两端只拉绳索 `tensionCables` 不是同一对象。

本轮恢复多体侧的载荷文件和工况生成。完整结构分析侧的载荷导入、节点分配、RBE3 生成及隐式结构求解依赖缺失的原结构子系统，本轮没有将这些流程标为已完成。BDF 回归检查生成卡片、编号、单位和数值，未运行第三方 Nastran 求解器。

## 接触设置与实际动力学核验

原线程和当前适配层都调用引擎 `ApplyContactFrictionSettings` / `ApplyImpactContactSettings`：关闭摩擦显式传入零系数；刚度、阻尼由界面 N 系转换为引擎内部 mN 系。原来的 `penetrationDepth` 零值默认行为已恢复，未设置或零值使用 `0.0254 mm`；它是阻尼达到全值的深度，不是允许压入量上限。负值仍由输入验证明确拒绝。

原 `doSolve` 将 `scenario->getUsePreset()` 原样传给 `InitSolver`，原线程和 PID 系统都没有额外调用 `SetStiffContact`。当前锁定引擎对 CONTACT 等预设准备 SMC 刚度/阻尼矩阵，自定义配置仍遵循原调用策略，适配层没有暗中更换用户选定的积分器或求解器。**自定义积分器可被正确选择，不代表任意时间步、刚度、阻尼和线性求解器组合均稳定。** 本轮自定义线性化配置的刚性接触试验出现能量增长，因此没有把它列为通过工况；通过的接触动力学回归明确使用 CONTACT 预设。

[NativeDynamics](../tests/MotionOccNativeDynamicsSmoke.cpp) 用真实导入的 10 mm 立方体和固定 CAD 平台，执行 1 kg 物体从 2 mm 高处落下的接触过程。接触刚度为 `1000 N/mm^1.5`、阻尼为 `1 N·s/mm`、指数为 `1.5`。分别用 `0.0005 s` 和 `0.00025 s` 步长计算至 `0.3 s`，检查：

- 下落速度实际超过 `100 mm/s`，确实发生碰撞。
- 冲击压入量不超过忽略阻尼的单接触能量界限，加一输出步内的碰撞检测行程。
- 最后质心高度位于 `4.9–5.1 mm`，竖直速度小于 `0.5 mm/s`。
- `0.25 s` 以后平均竖直加速度的绝对值小于 `50 mm/s²`，对应该质量的平均力不平衡小于 `0.05 N`。
- 步长减半后的末态高度差小于 `0.02 mm`；固定平台保持不动。
- 把阻尼全值深度改为零，结果与 `0.0254 mm` 默认值在同一步长下保持一致。
- 禁用接触后，同一几何和初始状态会自由落穿平台，排除仅固定显示姿态的假接触。

压入量界限由能量关系 `K*δ^(e+1)/(e+1) = mg*(h+δ)` 求得，本工况为 `δ=0.31758337 mm`。多接触点及耗散可减小压入量；测试没有把阻尼 ramp 深度误用为刚性挡板，也没有用观察到的压入量倒设阈值。末态步长收敛阈值在排查过程中保持 `0.02 mm`。

同一测试还运行四种真实闭环组合：直线位移或旋转角度传感器，反馈符号为 +1 或 -1。检查每一帧的 PID 反馈与实际传感器一致、输出限幅、1.5 s 内的目标收敛，以及实际体位移达到 10 mm、实际体转角达到 30°，防止传感器曲线变化而马达没有接管。

## 原代码已存在的限制，以及尚未全面验证的组合

| 项目 | 原代码实际状态 | 当前处理或验证边界 |
| --- | --- | --- |
| 加速度驱动 | `mMotionSolverThread` 明确抛出不支持错误 | 保持明确拒绝；位移/速度驱动已接通 |
| `Line` / `Centripetal` 运动副 | 翻译前就抛出不支持错误 | 不因保留枚举而宣称支持 |
| 泛型 `Coupling` 或裸 `joints.Gear` | 没有完整的独立约束参数路径 | 使用原成熟的 `couplings.Gear` / `GearRack` / `Cable` 路径；不悄悄建无效副 |
| 弹簧 PositiveOnly / NegativeOnly | 原弹簧翻译没有将这些方向开关传入引擎 | 明确拒绝失效选项；只拉和止挡使用独立的新力元 |
| TireForce / ForceField | 原矢量力兜底分支按 Torque 构建，没有实际轮胎/场模型 | 明确报错，不能用普通力矩冒充该模型 |
| PID 使用反力/驱动力传感器反馈 | 原 PID 实时反馈只接受体运动、距离和角度类传感器 | 保持范围限制；这些传感器仍可用作求解后的结果查询 |
| ADDM / BICGSTAB 选择项 | 有界面枚举，没有对应可用系统工厂路径 | 明确拒绝，避免静默换成默认求解器 |
| PARDISO / MUMPS | 需要对应第三方构建 | 当前云端构建不声称支持 |
| 接触力曲线 | 原 `mMotionResultData` / 结果查询服务没有接触帧或该通道 | 本轮没有伪造直接接触力时程；接触力平衡由质量及真实加速度核验 |
| AutoFlex 无效输入 | 原桥接可用默认钢材或最近节点兜底，创建失败后可能继续刚体求解 | 当前要求有效材料、真实网格、可验证附着编号；失败明确中止，避免错误模型被算成成功 |
| 完整网格/材料/求解器组合 | 原源码不是数值验证报告 | 本轮通过具体自动网格、悬臂、旋转附着、部分结果、PID 和接触工况，不声称覆盖全部组合 |

手动取消和物理提前终止仍是不同状态。取消不提交本次求解的半段结果；有限几何边界或模态发散则可以提交明确标记的有效前缀。有效性检查比原来的“跳过失败对象后继续”更严格，是为确保曲线与动画表示实际求解的同一个模型。

## 本轮专项回归结果

2026-11-21 在云端现有 Linux 构建执行下列三个目标，全部通过：

| CTest | 主要证据 |
| --- | --- |
| `MotionOcc.FlexResults` | 完整柔性结果数据、模态/总位移/原投影数值、正确插值、真实悬臂变形、401 帧旋转接口参考系、异常帧跨柔性体原子拒绝、发散有效前缀一致性 |
| `MotionOcc.LoadExport` | 真实静力载荷符号、力矩换点、CSV/BDF 内容、特征及同步工况、J 端分析体参考系、时刻合并、错误数据不覆盖旧文件 |
| `MotionOcc.NativeDynamics` | 四种传感器 PID 闭环、实际 CAD 冲击和静态平衡、步长减半、原零深度默认、无接触反例 |

复测命令（构建目录按本机配置替换）：

```sh
cmake --build build-cloud --target MotionOccFlexResultsSmoke MotionOccLoadExportSmoke MotionOccNativeDynamicsSmoke -j2
ctest --test-dir build-cloud -R '^MotionOcc\.(FlexResults|LoadExport|NativeDynamics)$' --output-on-failure
```

所有新增输入为测试自生成数据；没有修改或公开用户原模型文件。本页记录的是求解及后处理专项核验，不代替其余桌面、拾取和项目往返测试结果。
