# 原运动数据工作流与验证

本次恢复以 `GUI/src/MainWindow/mMotionSolverThread.cpp` 中实际接入 MotionEngine 的功能为基准。OCC 构建沿用原 Qt Widgets、Ribbon、模型树和停靠窗口，在这些已有入口接入完整模型；引擎锁定 `fff3dd3b5caf37a6d01e5ea5c9f89d7be5eafed4`，同时构建核心和 Modal。

可公开复测的自动测试与自生成窗口验证见 [回归记录](native-motion-verification.md)。

## 原点、方向、节点与函数编辑

坐标字段旁的拾取控件使用真实拓扑和网格：CAD 顶点、边、面、实体质心，以及 FEM 节点、网格边、网格面和单元。边可取中点或圆/椭圆中心，面可取面积质心；另有鼠标在实际曲线/曲面上的交点模式。方向支持全局轴、两点、边切向/回转轴、面法向/回转轴和反向。曲线/曲面副的专用选择器保存原几何 ID，并附加实际 OCC 编号及几何特征。

激活一个字段后，视口只向该字段返回结果，不会同时切换整部件编辑器。右键撤回最后选择，Esc 恢复激活前的值；方向反向与拓扑引用在保存、重开和再次进入拾取时保持。手工输入坐标解除旧几何引用。多选节点可 Ctrl + 左键拖动贯穿框选，包含遮挡节点。AutoFlex 改目标体、切回自动附着或打开节点列表前会结束旧拾取会话，防止旧网格节点被写入新体。

原点、marker 和力作用点沿用原始全局 CAD 坐标约定。传感器的 `referencePoint`、`pointA.localPos`、`pointB.localPos` 在界面显示全局点，存储时按所选体初始质心转为原求解器需要的局部点，重开时再恢复为全局显示。

从空模型新建单体或批量运动体，使用默认钢密度 `7.85e-6 kg/mm³` 对实际闭合 CAD 计算质量、质心与完整惯量矩阵。密度或部件绑定改变后重算，也可以显式启用自定义质量属性。已有 JSON 的质量属性在导入时保持原值，编辑时可按真实几何重新计算；无效/开放实体会提示，不能靠默认 1 kg 掩盖失败。

驱动提供公式、模板、表格和预览，力元公式字段提供其实际支持的 `t` 或 `x/v` 变量。预览和校验直接调用同一 MotionEngine 函数实现。驱动表格支持 CSV/TXT 交换；仅支持公式的力元不显示无法保存的时间表格。力元表达式保存到原字段，并更新对应启用开关，避免编辑成功却仍在计算旧常量。

## 从原文件开始

1. **主页 → 导入几何模型**，打开配套 STEP、IGES 或 BREP。STEP 装配的零件名称、实例位置及精确几何保留。导入成功后可自适应视图核对位置。
2. **主页 → 导入运动 JSON**，打开原 `.motion.json`。系统保留完整文档、原对象 ID、未知扩展和原求解方案，单独记录新 OCC 几何绑定。
3. 系统先用实例名称、质心和惯量确认运动体。原质心处于部件局部坐标时，可依据真实 STEP 装配变换及完整主惯量唯一识别，不移动 CAD 或改写质量属性。如仍出现绑定面板，选择该体实际拥有的全部部件；重合/重复实例不默认任选。原运动体 ID `0` 是有效对象，大地 ID 为 `-1`。
4. 曲线/曲面运动副先核验已保存的几何特征，再以旧全局编号、导入拓扑及排他几何证据恢复绑定；共享顶点和宽装配容差不能单独消除歧义。独立构造曲线可以作为参考线，导入的 CAD 必须实际包含它。无法确认时，面板列出真实部件、类型和坐标范围供选择；原 ID 保留，新几何特征随引用保存，便于以后编号变化时重识别。
5. 在模型树选择原求解方案，点击 **求解**。方案的原结束时间、步长、积分器、驱动表达式/表格等传给真实 MotionEngine。缺少材料、网格节点映射或其他必要信息会指出具体缺项；修正后再求解。
6. 求解完成后进入方案下的 **动画** 或 **运动曲线**。动画按实际采样时间查找状态，通过稳定 ID 对应运动体；多部件一起运动，柔性体使用真实模态节点。
7. 用 **保存**保留 `.mxmotion` 项目中的精确 CAD、运动文档、绑定和曲线配置。用 **导出运动 JSON**交换运动设置和曲线请求；再次单独导入 JSON 时仍需配套 CAD。

点在曲线上或点在面上副滑出真实几何边界时，沿用原线程的边界终止语义：界面明确显示终止运动副和时刻，保留此前已算出的结果供查看。它与完成原结束时间、用户主动取消、数值求解失败分别处理。

边界后的试算帧不会进入动画、曲线或 CSV。提示同时显示“尝试越界的时刻”和“最后有效结果时刻”，动画时间轴截止到后者。左侧模型树的分类、固定体/运动体、运动副、力元及方案结果节点复用原界面的图标资源，编辑或求解刷新后仍保留。

也可从命令行打开同一流程：

```sh
build-occ/bin/MxMotion /path/to/model.stp --motion /path/to/model.motion.json
```

## 自动柔性体：沿用选体、材料、网格、求解的流程

1. 完成几何与运动 JSON 导入后，在模型树编辑原自动柔性体，或通过 **自动柔性体** 命令新建，选择实际目标运动体。
2. 从材料下拉选择材料并核对 **弹性模量 MPa、泊松比、密度 kg/mm³**。已有 `materialId` 的参数会从材料记录带入，保存时写回同一材料。空材料库显示可编辑的“默认钢（请核对）”；旧 JSON 没有导出材料时，需要在这里补齐，求解不会自行猜测物性。
3. 设置单元尺寸、模态数量和阻尼，点击保存。已有体网格直接复用；没有体网格时，按目标体绑定的 CAD 部件调用真实 Netgen 划分，完成后立即显示网格，面板显示节点数和四面体数。可先在几何部件执行“生成网格”，再创建或求解自动柔性体。
4. 附着节点留空时按运动副自动收组。需要手动接口时，保存生成网格后点击 **选择附着节点**，在真实网格节点及坐标列表中勾选，或点击 **在视口拾取附着节点** 进行点选/框选；相邻节点按单元连接关系组成接口。手动接口优先，不再额外叠加自动运动副焊接点。可用 **清空手动节点，按运动副自动附着** 明确恢复自动方式。
5. 选择原求解方案并求解。真实 Modal 缩减使用保存/预览的同一份体网格；动画显示接受时间步中的实际变形节点。运动曲线可选择自动柔性体的模态坐标，曲线导出与动画沿用同一时间轴。
6. 保存 `.mxmotion`，或导出运动 JSON，材料和体网格随自动柔性体数据一并保存。项目再次打开后可查看网格状态并直接求解。

需要改变已有网格尺寸时，从几何部件执行“生成网格”；AutoFlex 的单元尺寸用于缺少网格时的自动划分。更换/删除网格或重绑几何后，旧手动节点编号须重新选择，界面与求解器会明确提示，避免把旧编号套到新网格。网格失败或取消保留先前有效网格。原 JSON 只有旧全局节点 ID、没有节点坐标或映射时，同样需要重新选择，无法凭数字还原原节点位置。

动画可选择弹性位移、总位移或原自由基投影云图，并选择当前帧/全时程色标范围。结果保留完整模态矩阵、四面体、接口位姿和逐帧模态坐标；插值时先计算向量再取模长。原自由基投影保留旧面板近似含义，不作为应力结果。模态发散时同步保留已接受的刚体、柔性、曲线和控制器结果，并明确标为提前终止，异常试算帧不写入结果。参考系与实际旋转回归见 [兼容核对](native-solver-compatibility-audit.md)。

## 曲线与专业载荷导出

可见曲线支持 CSV 或制表符 TXT，按照当前显示源、时间范围和真实接受帧导出。方案下的 **结果导出** 提供全部通道 CSV，以及手动载荷、特征工况和同步工况入口。

手动载荷可选运动副、可用耦合副或驱动器，选择 I/J 端、六分量、缩放、指定帧/最大综合载荷帧/全部帧，输出 CSV 或 BDF。目标点可手填、从 CAD 拾取或选择实际 FEM 节点，力矩按目标点正确换算。工况模式按局部极值和合量峰值选取时刻，按容差合并，并可在同一时刻收集全部所选副的载荷，转换到分析体初始参考系。

原始反力通道的 J 端语义、导出到 I 端的符号、力矩换点和单位均有实际静力回归。旧四端 Cable 耦合的现有结果不足以唯一恢复全部端口载荷，专业导出明确拒绝该来源；可用其导向副反力。结构侧载荷导入、RBE3 生成及隐式结构求解依赖缺失子系统，尚未在本 OCC 构建恢复。

## 新只拉绳索与止挡

两项位于 **连接与力元 → 柔性连接**，分别创建独立力元，并可在模型树中再次编辑、删除、保存和重新打开。

| 对象 | 设置 | 结果与物理行为 |
| --- | --- | --- |
| 只拉绳索 | 两端体、初始全局作用点、自由长度、刚度、阻尼、接合过渡宽度 | 松弛时力为零；绷紧后仅施加拉力；卸载阻尼不会变成推力 |
| 止挡 | 两端体、作用点、投影方向、全局/随体方向模式、上下侧、止挡坐标、刚度/指数或表格、阻尼及渐入深度 | 只有越过止挡时作用；回弹不产生粘附拉力；不会额外锁住其他自由度 |

长度为 mm，刚度为 N/mm（幂律止挡为 N/mm^指数），阻尼为 N·s/mm。旧的线缆耦合仍是双向位移关系，继续保留在耦合副中。新绳索不替换该约束。

曲线面板列出求解实际产生的通道，包括绳索拉力、长度/伸长、止挡接合状态与力等；标量、矢量和多分量通道按各自实际维度显示。可见曲线导出使用当前选择；完整结果 CSV 包含对象集合、稳定 ID、变量、分量和单位。

## 关键逻辑修复

- **原数据模型完整保留**：高级关节、力元、传感器、PID、接触与 AutoFlex 不再被简化为只有三种关节的轻量模型。
- **单位一致**：毫米—千克—秒的引擎内部力使用 mN，界面力使用 N；力矩、角度、扭转刚度、能量和材料单位分别换算。原 JSON 重力为 mm/s²。
- **正确初始状态**：初始装配的虚拟加速度估计不会给自由体留下人为初速度。
- **统一结果身份**：曲线通道按集合、ID 和变量定位；动画按运动体 ID 绑定全部 CAD 部件。ID 0、非连续 ID、世界坐标质心、多部件及模态位移均有回归。
- **正确时间轴**：采用实际接受时间步，并处理不能整除的真实尾步；长时累计浮点误差不会生成额外极短尾步和末端加速度尖峰。
- **几何完整性**：STEP 中可修复的无效拓扑只在精确包围盒、体积、面积、质心和惯量校验通过后接受。相切圆边界导致的平面网格失败使用同一精确曲面的分片三角化，原表面、边界、拓扑、位置及朝向不替换。
- **大型装配显示**：全装配展示网格超出预算时，逐级放宽显示三角化精度并重新生成全部部件，不丢弃零件。精确 CAD、质量属性、约束边面和求解用几何独立保留。
- **旧惯量格式**：运动体参数增加“惯量积约定”。新建 CAD 体使用真实惯量矩阵项；旧文档默认依据明确的六分量导出公式，或全部绑定 CAD 的质心与六分量惯量证据，确认是否需要转换正号惯量积。自定义质量属性保持原值，求解内部只按确认的符号约定转换；没有证据时不会靠惯量不合法反推符号。

## 可复测入口

先按根 README 完成构建。无桌面的后端检查：

```sh
ctest --test-dir build-occ --output-on-failure -LE desktop
```

各测试分别覆盖 CAD/Netgen、原轻量刚体、动画、原运动文档、项目保存、边面绑定、完整原生求解、曲线数据与 Qwt 配置。原生求解测试包含真实 Modal 和自动体网格，具有解析数值断言，不只是检查进程退出。

完整窗口流程需以 `MX_TEST_DESKTOP=ON` 构建，在支持 OpenGL 3.3 的桌面或 Xvfb/Mesa 会话中运行：

```sh
build-occ/bin/MxMotion --native-desktop-smoke build-occ/native-desktop-smoke
```

该测试生成可公开重现的 STEP 和原格式 JSON，使用真实界面执行：导入几何和 JSON → 创建/编辑止挡、只拉绳索、体点弹簧 → 保存并回读项目 → 求解 → 四条曲线 → CSV 和 JSON 导出回读 → 实际帧动画 → 播放、暂停、停止。测试对象故意采用原运动体 ID `0`、非连续 ID、不同的几何 ID 和方案 ID `0`。

同一入口还包含自生成悬臂体的 AutoFlex 流程：STEP/JSON 导入、引用材料编辑、保存后真实 Netgen 网格预览、实际节点选择及映射保存、真实 Modal 位移校验、模态曲线和变形帧动画、项目重开求解，以及重新导入不含网格的 JSON 后复用当前体网格。生成网格后会将工作进程路径临时指向不存在的位置，以验证后续步骤确实复用已有网格，而不是悄悄再次网格化。

可附加自己的原文件，继续通过同一界面完成求解和动画：

```sh
MX_NATIVE_SMOKE_CAD=/path/to/model.stp \
MX_NATIVE_SMOKE_MOTION=/path/to/model.motion.json \
build-occ/bin/MxMotion --native-desktop-smoke build-occ/native-desktop-smoke
```

对整套原算例进行原时长批量检查：

```sh
build-occ/bin/MotionOccNativeCases --cases /path/to/cases --report /tmp/native-cases.json
```

`--filter` 可按 JSON 路径筛选，`--bind-only` 只检查几何导入及绑定。一个目录有新旧多个 CAD 时，可为单个唯一 JSON 明确指定 `--cad /path/to/complete-model.step`，例如选择包含构造曲线的完整版本。重复 JSON 按 SHA-256 去重，原文件不修改。报告在每个算例结束后原子保存，区分 CAD 导入、体绑定、边面绑定、求解准备、数值求解和结果校验阶段；检查全部帧时间、有限数值、固定体、关节闭合、恒速驱动实际速度，以及点线/点面作用点到精确裁剪 BRep 的逐帧距离。正常原终时完成与几何边界终止分开记录。

用户算例的原 CAD、完整 JSON 和包含详细质量属性的临时诊断报告不随本代码提交。原始数据有歧义或缺项时，单独记录原因，不修改源文件、缩短时长或删除约束来制造通过结果。

## 原线程本身的边界

完整能力对应与参数格式见 [native-motion-backend.md](native-motion-backend.md)。原线程未完成实际接入的 `Line`、`Centripetal`、通用 `Coupling`、裸 `Gear` 运动副和加速度驱动继续报错；真实齿轮耦合副使用两组旋转副的轴心和传动比。仅有 `materialId` 的 AutoFlex 文档无法恢复未导出的材料数据库；仅有旧网格全局 ID 的附着点也不能凭空对应到重新划分的节点。界面支持补充这些实际数据后继续计算。

`ADDM`、`BICGSTAB` 虽出现在引擎枚举中，当前锁定引擎没有创建对应求解器的分支。导入不会丢失原选择，执行时明确拒绝；已支持的配置在初始化后再次核对实际求解器类型，避免引擎内部默认回退被误认为原方案已运行。
