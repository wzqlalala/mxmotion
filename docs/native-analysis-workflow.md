# 真实模态、独立柔性接口、静力预载与受限执行器

本轮在 `lite-occ` 的原生 Motion 文档和既有 Qt Ribbon、模型树、停靠参数面板中增加以下流程。已有 `.motion.json` 不需要增加新字段：分析默认仍为动力学，自动柔性体默认仍使用共用参考体的模态缩减。新字段随原生 JSON 和 `.mxmotion` 工程保存，未知扩展字段继续保留。

## 1. 求解前检查真实模态

1. 导入 CAD，绑定运动体，创建或编辑自动柔性体，填写材料、体网格和附着节点。
2. 保存面板。选择模型树中的该自动柔性体，点击“检查已保存柔性体的真实模态…”。可以在尚未创建动力学方案时运行检查。
3. 检查器显示请求阶数、实际保留阶数、频率 Hz、周期 s、截止频率、实际附着节点组以及模态基的边界条件。
4. 选择一阶振型，调整显示峰值幅值、相位或观察速度；可播放振型并显示实际附着节点。“相位”滑块用于查看该振型的正向峰值、零位和反向峰值，不是输入角度。观察速度与真实频率分别标注。
5. “导出频率与振型 CSV”导出真实频率、参考坐标、求解器原始振型分量及归一化分量。节点索引从 0 起，与内嵌四面体网格一致。

检查器从真实四面体刚度和质量矩阵取得特征解，保存的是求解器振型；显示时按该阶最大节点位移范数归一化。显示幅值是观察参数，不能作为工况下的实际变形。固定接口模态将全部附着区夹持，与整机在工作构型处的固有模态含义不同。自由体模态可能包含近零频率的刚体模态。

检查使用已保存求解定义的独立快照，准备时可补入当前已生成的真实体网格快照。它不推进动力学时间，不用振型预览修改原几何、材料或载荷，也不覆盖已有时程。面板上尚未保存的修改不会进入检查，修改后应先保存。求解后的动画面板同样可打开结果中保存的真实模态基。附着条件或频率截断使保留阶数减少时，显示实际数量；没有可显示模态时返回明确原因，不补零振型凑数。

没有附着区的自由体可单独检查自由模态；将其作为运动模型中的柔性体参与动力学时，需要先建立实际接口，避免原运动体与有限元网格成为两个没有连接的对象。

共用参考体的 CMS 缩减要求合并去重后的附着节点至少包含 3 个不共线节点，以消除网格相对参考体的刚体自由度。当前静态约束模态构建不支持把单点或共线附着解释为铰接接口；自动附着半径选点不足时会报告具体原因，需要按真实几何调整附着区或重新选点，不会添加虚拟节点或悄悄扩大半径。

## 2. 真正的独立接口刚柔耦合

自动柔性体面板新增“接口耦合方式”：

| 模式 | 动力学表示 | 接口语义 |
| --- | --- | --- |
| 共用参考体 `SharedBody` | 既有模态缩减 | 所有附着片与同一个参考体相连，片之间保持刚性相对位姿 |
| 独立接口 `Independent` | 共回转 tetra4 全有限元 | 各附着片有独立接口体，之间由真实有限元的质量、刚度和节点自由度耦合 |

### 建模步骤

保留原运动体、运动副和载荷定义，在自动柔性体中选择“独立接口”。至少设置两个接口片，每片至少包含三个不共线节点，各片不重叠。

未指定副分组时，“按运动副自动附着”按不同运动副作用点建立端口；相同作用点的副共用一个端口。也可以点击“设置独立接口的运动副分组…”，取消“按运动副位置自动分组”，新增接口组并勾选该组的运动副；全部相关副必须各分配一次。显式节点组与显式副分组同时存在时，按组序号对应；只有节点组时，运动副按作用点对应最近接口，等距歧义会报错。

“按运动副自动附着”清除手动节点、节点组和附着位置，但保留已设定的运动副分组；要恢复副位置自动分组，在分组对话框中重新勾选自动选项。更换目标体时，旧网格附着和副分组会一起清除，需对新目标体重新确认。高级 JSON 的 `attachGroups` 使用当前内嵌网格从 0 开始的节点索引；界面拾取的 `attachPoints` 则保留实际网格节点 ID，并通过 `mesh.nodeIds` 映射。

准备求解时，只在不可变求解快照中生成内部端口并重绑相应副、载荷、Marker 和传感器。保存的设计仍保留原实体 ID。原运动体质量由真实网格质量替换，接口自身不再额外叠加刚体质量；两个接口不能继续被同一个原刚体强行锁在一起。真实节点位移、独立接口位姿、动画和弹性位移云图使用同一结果时间轴。

独立接口模式的“模态数”和“截止频率”用于模态检查，动力学保留全部有限元节点自由度。即使没有内部夹持模态，只要接口间的有限元模型有效，独立接口仍可产生真实弹性形变。全有限元支持无阻尼或材料瑞利阻尼；每阶模态阻尼比适用于缩减模型，在独立接口模式下会提示并要求选择可用阻尼模型。

### 载荷和测量点的含义

本轮接通的是刚性附着接口与柔性结构之间的传力。原运动体上的点载荷、Marker 和测量点会按初始作用位置路由到最近接口；测量点的 COM 局部坐标会转换，保持原世界位置。该操作保持力及力矩作用于选定接口的含义，不等于直接加载或测量任意内部有限元节点。

高级 JSON 可通过 `flexInterfaceIndex` 或对应字段的 `InterfaceIndex` 显式指定接口，编号从 0 起。例如载荷 `bodyIdInterfaceIndex`、体传感器 `targetBodyIdInterfaceIndex`。姿态参考没有唯一测量点，默认采用首接口，可用 `referenceBodyIdInterfaceIndex`、`bodyAIdInterfaceIndex`、`bodyBIdInterfaceIndex`、`axisBodyIdInterfaceIndex` 指定。几何拾取和常规端点位置仍使用原有坐标约定。

独立接口当前采用全有限元求解，计算量随网格节点数增加。柔性 CAD 自身作为点在线/点在面副的导轨、原刚体 CAD 接触壳作为变形接触面，尚未接入变形几何更新，因此会明确拒绝；将相应导轨或接触部件保留为独立刚体可以继续使用已有几何约束流程。

## 3. 静力平衡与预载后动力学

求解方案增加 `analysisType`：

| 类型 | 初始处理 | 输出 |
| --- | --- | --- |
| `Dynamic` | 原有装配和速度一致性处理 | 动力学时程 |
| `Static` | 在 t=0 载荷、零速度下求平衡 | 一个收敛的平衡帧，含位姿、载荷和柔性变形 |
| `PreloadedDynamics` | 先求静力平衡，再保留内部变形启动动力学 | 从受载平衡状态开始的时程 |

静力迭代使用真实引擎载荷和约束残差。小系统对实际载荷进行切线求导，较大的有限元系统使用实际稀疏刚度块。静力求解过程中使用适合该切线系统的直接求解器，结束后恢复方案的动力学求解器。

`staticMaxIterations`、`staticTolerance`、`staticConstraintTolerance`、`staticStepDamping` 分别控制最大迭代次数、归一化力/力矩平衡容差、引擎约束残差容差和 Newton 步长阻尼。力平衡残差使用当前广义力残差的无穷范数，除以固定的初始广义载荷无穷范数（归一化分母至少为 1，使用引擎单位）；`staticTolerance` 因此是无量纲相对容差。约束残差沿用引擎方程的尺度，包含位移与转角约束，不将它统一标成 mm。日志报告最终残差和迭代次数；没有平衡、切线系统不一致、迭代耗尽或残差未降低时返回失败，保留已有结果，不以零增量代替收敛判断。

预载后动力学保留原网格参考构形与内部应变；初始平衡不会被重定义成新的无应力形状。弹性位移显示也保留预载变形。若 t=0 的运动驱动规定非零速度，则不满足静止平衡条件，会提示调整初始驱动或采用动力学。静力方案不能运行离散 PID；预载后动力学会在静力完成后启动 PID。

## 4. 力/力矩执行器与受限伺服

原驱动编辑器在位移、速度模式之外增加：

| 控制模式 | 目标自由度 | 输入单位 | 实现 |
| --- | --- | --- | --- |
| `Force` | 平移 | N | 实际线性力电机 |
| `Torque` | 旋转 | N·mm | 实际力矩电机 |

执行器沿目标运动副自由轴施加力或力矩，保持被动运动副本身的其他约束。执行器不增加目标自由度上的运动约束，运动由真实惯量、载荷与约束决定。输入支持原表达式和时间表格。

`effortLimit` 为实际力/力矩幅值上限，`powerLimit` 为机械功率绝对值上限 W，`noLoadSpeed` 为驱动方向的空载速度包络（mm/s 或 °/s）。值为 0 时不启用相应上限。空载速度包络需要正的力/力矩上限；超过空载速度后仍保留限幅内的制动能力。求解过程按当前速度持续计算实际限值。

结果新增 `EffortCommand`、`EffortApplied`、`MechanicalPower`、`EffortLimited`，分别表示请求量、实际输出、机械功率和限幅状态。力驱动的真实运动量以 `Coordinate`、`Rate`、`CoordinateAcceleration` 输出；原规定运动驱动保留 `ImposedValue`、`ImposedSpeed`、`ImposedAcc`。原 I/J 端力与载荷导出约定继续使用。

PID 可接管速度驱动以及上述力/力矩执行器。受限执行器 PID 的输出使用 N 或 N·mm，反馈和目标使用其显示的工程单位，旋转执行器直接自由度反馈使用 ° 或 °/s；既有速度 PID 的直接旋转反馈继续沿用 rad 或 rad/s 约定。旧速度 PID 使用角度传感器时，目标仍按 ° 输入，误差和增益计算转为 rad，输出为 rad/s；面板分别标注目标与增益单位。原速度 PID 的 `outputLimit` 限制给定速度。力/力矩 PID 的积分抗饱和同时考虑控制器 `outputLimit` 和执行器的力/功率/速度包络。

反力反馈需要单独定义步内采样契约，本轮仍明确阻止 `JointReaction` / `DriveActuation` 用作 PID 反馈；这些传感器继续可用于结果观测。旧加速度规定运动入口仍无完整原生实现，界面会说明其原因。

## 5. 三个专用参数面板

- **求解方案**：按时间、环境、预设、高级参数、静力初始化分组；显示含初始帧和终止帧的预计输出帧数；显示真实生效的积分器和求解器。柔性体、接触、单边力元及曲线约束导致的选择变化会解释，未生效字段保持原值并禁用编辑。直接矩阵求解器不使用线性迭代次数或容差；原 `integratorBeta` 字段目前仅保留，Newmark 实际使用引擎默认 γ=0.6、β=0.3。
- **传感器**：类型决定目标对象、变量列表、点坐标与方向控件。实际测量量使用中文和单位，不再要求记内部枚举字符串；切换类型时保留原坐标及扩展字段。
- **PID**：根据反馈源、目标源和执行器类型显示相应输入；目标、反馈、输出单位分开显示；不支持的组合在提交配置前给出具体原因。目标选择“固定目标值”时保存 `targetInputId=-1`，不会让隐藏的旧轨迹继续接管；选择“控制输入轨迹”时须选有效输入，常量目标字段禁用。向量传感器反馈必须选择 X、Y、Z 或幅值，不能把“所有分量”传给标量 PID。

这些面板沿用原生字段工厂及已经恢复的 CAD/FEM 拾取控件，几何编号和局部坐标转换不另起一套约定。导入后编辑、保存和再次打开继续保留原 JSON 扩展字段。

## 6. 验证入口

在已配置的构建目录运行：

```bash
cmake --build build-cloud -j3
ctest --test-dir build-cloud -LE desktop --output-on-failure -j2
```

新增的物理和结果验证入口：

- `MotionOcc.Modes`：真实频率与 E、ρ 的平方根缩放关系，夹持节点振型为零，实际阶数/截止频率，原始基不被预览改写，CSV 原子导出，全有限元云图移除刚体运动并保留预载。
- `MotionOcc.IndependentFlex`：独立端口轴向梁解析柔度、质量与重力仅计一次、预载保持、零内部模态的边界柔度、共回转刚体转动客观性。
- `MotionOcc.StaticServo`：kx=mg、T/k、无平衡失败、迭代上限、取消、实际 F/m 与 T/I 加速度、I/J 输出符号、执行器限幅和受限闭环响应。

实际 Qt/OpenGL 桌面入口为 `MxMotion --modal-desktop-smoke <输出目录>`，验证保存工程后直接运行模态检查、频率/附着节点表、振型切换、相位、播放、实际渲染与 CSV 导出，并通过真实窗口求解独立接口全有限元静力，检查单平衡帧与弹性位移云图。已有 `--native-desktop-smoke` 增加三类专用面板及新执行器配置的保存/重开检查。完整结果及运行环境见 [native-motion-verification.md](native-motion-verification.md)。
